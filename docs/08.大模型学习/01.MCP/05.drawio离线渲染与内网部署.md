# draw.io离线渲染与内网部署

本地进程只是部署位置，离线能力取决于编辑器、布局资源、依赖和模型的整条链路。

> 配置项依据本地 `@drawio/mcp 1.10.0` 源码核对；桌面版和内网网页部署是两条独立路线。

## 1. 没有外网能用吗？

MCP 协议不要求公网。关键是模型、工具程序以及下游依赖是否都在内网。

本地版本的 draw.io MCP 默认仍有外网依赖：

| 依赖 | 默认行为 | 内网处理方式 |
| --- | --- | --- |
| 编辑器 | 打开 `app.diagrams.net` | `DRAWIO_BASE_URL` 指向内网编辑器 |
| ELK 布局代码 | 按需从 CDN 下载 | `DRAWIO_ELK_URL` 指向本地或内网资源 |
| 图形索引 | 按需下载并缓存 | `DRAWIO_SHAPE_INDEX_URL` 指向本地或内网索引 |
| 图标搜索 | 补充查询在线图标 | `DRAWIO_ICON_SERVICE_URL=off` |
| 连线路由辅助代码 | 固定公网资源地址、带缓存 | 修改资源来源，或不调用该功能 |
| 安装后脚本 | 尝试预取路由代码 | 离线安装时预处理安装脚本和资源 |

缓存能减少下载，但不能直接当成“从不访问公网”的保证。严格隔离部署需要固定程序和资源版本，并断开外网验证完整调用链。

### 只需要文件或图片，不想部署网页怎么办？

只要可编辑文件：生成 XML 后写为 `.drawio` 即可，不必渲染。

需要图片：安装 **draw.io Desktop**，本地调用导出命令。例如 macOS 安装到默认位置时：

```bash
"/Applications/draw.io.app/Contents/MacOS/draw.io" \
  --disable-update \
  --export --format png \
  --output diagram.png \
  diagram.drawio
```

这是另一条需要接入的实现路径，当前 `open_drawio_xml` 不会自动执行它。服务器环境中，桌面版导出还可能需要虚拟显示等运行依赖。

桌面版免费，可从 [官方发布页](https://github.com/jgraph/drawio-desktop/releases)下载安装。其代码随应用提供，严格离线时关闭更新，并避免图中引用公网图片或字体。许可和离线机制见 [官方 Desktop 说明](https://github.com/jgraph/drawio-desktop)。

内网网页部署则是把 draw.io 网页应用放到内网服务器，供浏览器访问；它与安装桌面软件是两种选择。

银行等隔离网络在技术上可以采用“内网模型 → 内网 MCP → 本地图形文件 → 本地导出”。能否实际使用，仍取决于所在机构的软件准入、开源许可证和依赖审查。
